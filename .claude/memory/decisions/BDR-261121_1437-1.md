# BDR-261121_1437-1 — Historique : clé séparée, archivage auto, fusion par id

**Décision** : l'historique des parties vit dans un store Zustand séparé (`src/store/historique.ts`), persisté dans IndexedDB sous `skyjo-scan:historique`, au format versionné `{ version: 1, parties }`. Logique pure dans `src/lib/historique.ts`, testée dans `tests/historique.test.ts`.

- Une partie **terminée** est archivée dès sa dernière manche (`validerManche`) ; une partie **abandonnée** l'est au moment de la quitter, seulement si au moins une manche a été jouée. Une partie déjà archivée (même `id`) n'est jamais réarchivée.
- Stats : une partie abandonnée compte pour ses manches (moyenne, meilleure/pire), ni comme partie jouée ni comme victoire. Joueurs regroupés par prénom normalisé (`trim` + casse ignorée), affichés dans l'orthographe la plus récente.
- Grilles (E5-S6) : `Partie.grilles[m][j]` garde les grilles corrigées de chaque manche, valeurs seules (`valeur`, `dos`), sans les doutes du scan ni la photo.
- Export JSON ; import validé à la main (pas de zod) puis **fusionné par `id`** : rien n'est écrasé ni dupliqué ; un fichier de version plus récente est refusé.
- Pas de limite de taille de l'historique pour l'instant.

**Pourquoi** : une clé séparée permet de vider la partie en cours sans toucher à l'historique. Archiver en fin de partie (et pas seulement au clic « Nouvelle partie ») évite de perdre une partie finie si l'app est fermée. La fusion par `id` rend l'import sûr sur un téléphone qui a déjà des parties. Garder les grilles prépare le jeu de données vérifié de l'option C de la vitesse.

**Alternatives considérées** : historique dans la même clé que la partie ; archivage au seul clic « Nouvelle partie » ; import qui remplace tout l'historique ; exclure totalement les parties abandonnées des stats.
