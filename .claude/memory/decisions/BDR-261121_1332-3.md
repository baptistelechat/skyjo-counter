# BDR-261121_1332-3 — Moteur et modèle en Cache API depuis le worker

**Décision** : `cactus.wasm` et `mirage.cact` ne sont pas précachés par le service worker. `src/worker/cactus.worker.ts` les lit dans le cache `skyjo-modele-cactus-4.1.4` s'ils y sont, sinon les télécharge puis les y range. Le SW (`vite-plugin-pwa`, `globIgnores` sur `models/` et `cactus/`) ne précache que l'app (37 fichiers, ~757 Kio avec les polices).

**Pourquoi** : avec le précache du snippet du PRD, la première visite télécharge le modèle deux fois (le worker pour s'en servir, le SW pendant son installation), soit ~42 Mo pour des joueurs souvent sur un mauvais réseau. Vérifié en `pnpm preview` : SW actif, app rechargée serveur coupé.

**Alternatives considérées** : précache Workbox (`maximumFileSizeToCacheInBytes` 30 Mo, snippet PRD) ; `runtimeCaching` CacheFirst côté SW (la première requête part avant que le SW contrôle la page, donc pas mise en cache).

**Contrainte** : renommer `CACHE_MODELE` à chaque nouvelle version du moteur ou du modèle, sinon l'ancien binaire reste servi. Un quota dépassé ou une navigation privée désactive seulement le hors-ligne.
