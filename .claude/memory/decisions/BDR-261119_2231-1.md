# BDR-261119_2231-1 — Vitesse : option A pour le MVP, B et C documentées

**Décision** : le MVP assume l'attente d'un scan (6 à 45 s) : grille provisoire après chaque passe, correction manuelle d'un tap, consignes photo pour éviter les passes de recadrage et de rotation. Les options B (app native Capacitor + `libcactus.a`, CPU ARM/NPU) et C (détection + couleur + petit classifieur de chiffres en ONNX Runtime Web) sont détaillées dans `docs/vitesse-options.md`. L'objectif PRD « < 3 s » est abandonné pour E3.

**Pourquoi** : le build WASM de Cactus est mono-thread, sans WebGPU, et le moteur C n'est pas publié (impossible de le recompiler). B quitte l'esprit PWA « une URL, rien à installer ». C demande un jeu de données annoté. Les grilles corrigées dans l'app pourront alimenter C : y passer vers ~500 cartes annotées.

**Alternatives considérées** : B tout de suite (rapide mais app installée) ; C tout de suite (bloqué sans données) ; réduire la photo ou `max_tokens` (sans gain, ou casse la détection).
