# LRN-261118_2357-6 — cactus.js ignore locateFile : passer wasmBinary

**Pattern observé** : le build Emscripten de `cactus.js` (4.1.4) définit son propre `locateFile(path)` interne (`scriptDirectory + path`) et n'honore pas `Module.locateFile`. Dans un Web Worker Vite, il cherche donc `cactus.wasm` à côté du worker (`/src/worker/` en dev, `/assets/` en prod) et reçoit le HTML de l'app : « expected magic word 00 61 73 6d, found 3c 21 64 6f ». Il honore en revanche `Module.wasmBinary`. Autres points tranchés : build en WASM_BIGINT (`_cactus_load(ptr, BigInt(n))`), `Module.HEAPU8` est rafraîchi après croissance mémoire, le moteur copie le modèle (on peut libérer le buffer après `cactus_load`).

**Contexte** : E1, worker `src/worker/cactus.worker.ts`.

**Application future** : télécharger soi-même le `.wasm` (avec contrôle `response.ok`) et le passer en `wasmBinary` ; vérifier dans le JS généré qu'une option `Module[...]` est vraiment lue avant de compter dessus.
