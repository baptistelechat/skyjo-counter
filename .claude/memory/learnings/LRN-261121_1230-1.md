# LRN-261121_1230-1 — Tester un upload photo sans sélecteur : fetch + DataTransfer

**Pattern observé** : le serveur de dev Vite sert tous les fichiers de la racine du projet, donc une fixture du repo est accessible à `/tests/fixtures/<nom>.jpg`. Depuis `javascript_tool` (browser pane), on peut simuler le choix d'une photo :

```js
const blob = await (await fetch('/tests/fixtures/reel-48-mwmlrnvn.jpg')).blob();
const dt = new DataTransfer();
dt.items.add(new File([blob], 'photo.jpg', { type: 'image/jpeg' }));
const input = document.querySelectorAll('input[type=file]')[1]; // « Galerie », sans capture
input.files = dt.files;
input.dispatchEvent(new Event('change', { bubbles: true }));
```

Le parcours de scan réel (worker, Mirage, grille provisoire, score) est alors testé de bout en bout, avec de vraies photos dont on connaît le score attendu, sans le sélecteur natif que l'agent ne peut pas piloter.

**Contexte** : tests du mode partie de Skyjo Scan le 21/11/2026. `SaisieJoueur.tsx` a deux `<input type="file">` (« Photo » avec `capture="environment"`, « Galerie » sans). Résultats : `reel-48-mwmlrnvn` → 48 en 12 s, `reel-66-mwmmd09y` → 66 en 25 s même avec un scan précédent abandonné dans la file. Le dev server est en HTTPS (mkcert) : ouvrir `https://localhost:<port>`, `http` donne une page d'erreur.

**Application future** : rejouer ce test après toute modification du scan (`moteur.ts`, `cactus.worker.ts`, `lecture.ts`) en plus des tests Vitest, pour valider le parcours UI complet. Mesurer en boucle (`innerText` toutes les 500 ms) pour noter le temps d'arrivée de la grille provisoire et finale.
